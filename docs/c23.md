# C11 -> C23: what it would buy, what it would break

Research from 2026-11-21: ctui stays at `-std=c11` for now. The parts that
work at C11 are done (below); the rest waits on a coordinated bump across
every repo that vendors ctui. ctui-wm's `notes/dsp-attributes.md` did the
same exercise for c-µdsp and ctui-daw (no breakage, nothing worth taking
yet); this note is ctui's side of it.

## Tried

gcc 16.2 / clang 23.1 / glibc 2.44. Every `-std=c11` swapped for `c23` in
scratch copies of each repo:

| repo | at `-std=c23` |
|---|---|
| ctui | `make all` and `make test` (35 suites) clean, after one rename |
| ctui-mus | tests pass; `all` stopped only on that same rename (its vendored ctui) |
| ctui-daw | `all` + `test` clean (doesn't build `src/vk/`) |
| ctui-wa | builds; one test failed only for its gitignored test data |
| ctui-wm | the only C23 error was that same rename |

A `-std=c11` -> `-std=c23` bump is close to free. What it buys is mostly
tidier code, not speed.

## What breaks

- **`free_sized`**. C23 adds `free_sized()` to `<stdlib.h>` and glibc
  declares it in C23 mode, which collided with a static helper in
  `src/vk/vk.c`. Renamed to `sized_free()`: gcc 15+ defaults to `gnu23`, so
  any build without an explicit `-std` already hit it.
- **`c23`, not `gnu23`.** A strict `-std` keeps gcc's
  `-ffp-contract=off`; any `gnu*` mode makes it `fast` and FMA appears.
  ctui-wm's note measured 41 of 45 c-µdsp objects changed. ctui-daw passes
  the flag itself; ctui-wm and ctui-mus don't.
- **Toolchains.** ctui-daw supports Ubuntu 24.04, whose gcc 13 knows
  `-std=c2x` but not `c23`. `#embed` needs gcc 15 / clang 19. ctui-wm also
  builds on musl, and musl's `<stdbit.h>` is unchecked.
- **One bump for every repo.** ctui-wm, ctui-mus, ctui-daw and ctui-wa
  compile ctui's `.c` files with their *own* `-std=c11` (ctui-wa through its
  `BASE`). Any C23 syntax anywhere in ctui, not just in `ctui.h`, breaks them
  all until each Makefile moves too. This is the real cost.
- Nothing else: no empty-paren declarations (`f()` now means `f(void)`), no
  names of our own that clash (`bool`, `static_assert`, `typeof`,
  `unreachable`, ...).

## Done at C11

- `sized_free()` (above).
- `ctui_logf()` carries `format(printf, 2, 3)` (`core/log.h`, behind
  `__GNUC__` like `widget.c`'s `noinline`): its format strings weren't
  checked at all before. Every existing call already passed.

## Waiting on a bump, best payoff first

- **Unnamed parameters** in function definitions: the 232 `(void)self;` /
  `(void)ctx;` / `(void)ev;` lines, mostly in widget callbacks, go away.
- **`#embed`** for `src/vk/fonts/*.ttf` instead of the xxd + sed rule and
  its 1.7 MB generated header. Measured on that font: gcc 46 -> 13 ms,
  clang 267 -> 22 ms, `.rodata` byte-identical. The shaders could follow:
  glslc emits `.spv`, embedded under `alignas(uint32_t)`.
- **Enums with a fixed type** (`enum : unsigned char { CTUI_ATTR_BOLD, ... }`):
  `CTUI_CELL`'s fields could have real enum types and keep the
  20-byte static assert. Small gain: debuggers show names.
- **`[[nodiscard]]`**, selectively: on 0/-1 functions where ignoring the
  failure is a bug (init, file/save, allocation), never on the 1/0
  "visible change" handlers. Works today as
  `__attribute__((warn_unused_result))` if one earns it first.
- **`[[deprecated("use X")]]`** for renaming an API across the vendoring
  repos: they get warnings, not broken builds. Also available today as
  `__attribute__`; added when a rename needs it, not ahead of time.
- **`<stdckdint.h>`** for sizes read from untrusted files (look/, json/,
  xml/ parsers). `__builtin_mul_overflow` does the same at C11 already.

## Not worth it

`constexpr` for the numeric `#define`s, `nullptr`, `bool` (ctui is `int`
throughout, consistently), `typeof`/`auto` (no generic macros need them),
`[[fallthrough]]` (`-Wextra` is clean), `unreachable()`, `= {}`,
message-less `static_assert`.

## If the bump happens

Strict `-std=c23` in every repo in one go, ctui first, each consumer's
Makefile in the same go. First settle whether ctui-daw still needs Ubuntu
24.04's gcc 13 (`-std=c2x` there, and no `#embed`).
